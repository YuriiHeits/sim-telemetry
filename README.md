# StintLogger

**Версія: 1.1.0** — NeckFX `OFF` тепер і справді вимикає ефект живцем (раніше
міг не діяти, якщо CSP керував головою через `[SCRIPT]`), і кнопку `NeckFX`
можна сховати/показати з трею — за замовчуванням вона вимкнена.

Логер телеметрії для **Assetto Corsa** і **Assetto Corsa Competizione**. Сам
визначає, яка гра запущена, і пише CSV на кожен виїзд — по одному файлу на стінт,
з тим набором колонок, який ця гра реально заповнює.

Файл **закривається на в'їзді в піти або коли ти зупинився**, тому його можна
читати не виходячи з гри.

Windows, Python 3 + tkinter, тільки стандартна бібліотека. `pystray` і `Pillow`
опціональні — з ними з'являється іконка в треї.

## Що воно робить

- **Автовизначення гри** по процесу (`acs.exe` / `acs_x86.exe` → AC,
  `AC2-Win64-Shipping.exe` → ACC). Можна вийти з однієї гри й зайти в іншу не
  перезапускаючи логер — поточний файл закриється, наступний відкриється з
  правильним заголовком.
- **Розрахунок палива**: витрата на коло, скільки кіл лишилось, скільки літрів
  треба щоб дотягнути до кінця сесії, і скільки — на довільний відрізок у хвилинах.
- **Невалідні кола червоним** у списку кіл, і вони не забирають собі «найкраще
  коло» та не псують середню витрату.
- **Тиск і температура шин** у вікні.
- **NeckFX** — перемикач пресетів руху камери для AC, кнопка в вікні вимкнена
  за замовчуванням (пункт трею **Show NeckFX button** показує/ховає її). Читай
  попередження нижче.

## Запуск

**Готовий exe:** візьми `StintLogger.exe` зі
[Releases](../../releases), поклади в будь-яку папку і запусти.

Windows SmartScreen і частина антивірусів лаються на будь-який exe, зібраний
PyInstaller одним файлом — це відома проблема самого пакувальника, не ознака
чогось поганого конкретно тут. Якщо не довіряєш — запускай з джерел, там видно
кожен рядок.

**З джерел:**

```
python stint_logger.pyw
```

Потрібні `stint_logger.pyw`, `sim_shm.py` і `fuel_model.py` в одній папці.
Для іконки в треї: `pip install pystray pillow` (без них працює, просто без трею).

## Куди пишуться файли

Поряд із програмою:

```
<трек>/<машина>/<дата>/<час>_<гра>_<тип сесії>.csv
```

наприклад `red_bull_ring/bmw_m4_gt3/2026-08-05/11-23-14_ACC_PRACTICE.csv`.

Якщо папка з програмою незаписувана (наприклад ти поклав exe у `Program Files`),
логи йдуть у `Documents/StintLogger/`. Кнопка **Open folder** у вікні відкриває
те місце, яке використовується насправді.

## Колонки CSV

Спільні для обох ігор:

| колонка | що це |
|---|---|
| `t` | секунди від початку запису |
| `lap` | завершених кіл |
| `pos` | позиція на колі, 0.0…1.0 |
| `speed_kmh`, `rpm`, `gear` | швидкість, обороти, передача |
| `gas`, `brake`, `clutch`, `steer` | газ, гальмо, зчеплення, кут керма |
| `gx`, `gy`, `gz` | перевантаження |
| `slip_*` | пробуксовка по колесах |
| `press_*` | тиск у шинах, psi |
| `ttemp_*` | температура шин (core), °C |
| `susp_*` | хід підвіски |
| `tc`, `abs` | активність TC і ABS |
| `fuel` | паливо в баку, л |
| `inpit` | ознака піта від гри |
| `last_ms`, `best_ms` | останнє й найкраще коло, мс |
| `session`, `race_pos` | тип сесії, позиція в заїзді |
| `heading`, `vel_x/y/z` | напрямок і вектор швидкості |

Тільки **AC**: `camber_*`, `dirt_*` (забруднення шин), `tyres_out` (скільки коліс
за межами трека), `drs`.

Тільки **ACC**: `btemp_*` (температура гальм), `ideal_line`, `valid_lap`,
`fuel_x_lap` і `fuel_est_laps` (власні розрахунки гри по паливу).

Набори різні не з примхи: ACC не заповнює `camber_*`, `dirt_*`, `tyres_out` і
`drs` — там були б нулі, а AC не має нічого з ACC-екстри.

## Як рахується паливо

На кожному перетині лінії беремо рівень палива і час кола. Витрата кола — це
різниця з попереднім перетином. У середнє йдуть **три останніх валідних кола**;
коло відкидається, якщо на ньому була дозаправка, піт, або воно невалідне.

Перше число з'являється лише після **другого** перетину — з одного кола витрати не
видно, і краще показати прочерк, ніж вигадане значення.

`TO SESSION END` бере час, що лишився в сесії, і додає **одне коло** — таймерна
гонка завершується колом уже *після* нуля на таймері. `PLAN` рахує те саме для
кількості хвилин, яку введеш сам (значення зберігається в `logger.cfg`).

## Невалідні кола

В **ACC** беремо прапорець самої гри (`isValidLap`). В **AC** такого поля немає,
тому виводимо з `tyres_out`: усі чотири колеса за межами трека = коло невалідне.
Це стандартне правило AC/ACC.

Ознака **запам'ятовується на все коло**. Так треба: ACC скидає свій прапорець
назад у «валідне» рівно в момент перетину лінії, тому якби ми читали його тільки
там, зрізане коло виглядало б чистим.

Побічний ефект, який не є багом: коло виїзду з боксів у ACC завжди невалідне, тому
воно буде червоним.

## NeckFX — уважно

Кнопка `NeckFX` перемикає режими руху камери — `MINE`, `OFF`, `DRIFT`, `GRIP` —
і для цього **редагує конфіг твоєї гри**:

```
assettocorsa/extension/config/neck.ini
```

Перед першою правкою поряд створюється копія `neck.ini.ggbak`. Саме її повертає
режим **`MINE`**: твої власні налаштування NeckFX, якими вони були до першого
дотику інструменту, одним кліком і цілим файлом — разом із секціями, для яких у
нас пресетів немає (зокрема скриптовим NeckFX). Кнопка показує `MINE` завжди,
коли конфіг не збігається з жодним нашим пресетом точно — тобто твоє власне
налаштування ніколи не буде виглядати як наш `DRIFT` чи `GRIP`.

Знімок `.ggbak` один і робиться раз. Якщо ти правив `neck.ini` вручну вже після
того, як користувався кнопкою, або CSP перезаписав файл сам — `MINE` повернe
старіший стан, а не останній. Історії версій ми не ведемо.

Зміни підхоплюються при повторному вході в сесію — окрім `OFF`, який ще й
зануляє рух живцем на льоту (і примусово вимикає `[SCRIPT]`, бо доки скрипт
активний, він ігнорує ці значення — саме тому старі версії `OFF` могли не
діяти, поки не перезайдеш у сесію).

Це фіча Custom Shaders Patch, тобто існує **тільки в AC**. Під ACC блок кнопки
просто зникає з вікна. Якщо CSP не встановлений або гра не знайдена — кнопка
напише `neck.ini not found` і нічого не зробить.

Кнопка в вікні за замовчуванням **вимкнена** (нічого не ламає — просто не
займає місце, поки не потрібна). Показати/сховати — пункт трею **Show NeckFX
button**; стан пам'ятається в `logger.cfg`.

Не хочеш, щоб інструмент торкався конфігів гри — просто не тисни цю кнопку,
на логування вона не впливає.

## Аналізатори

Прості скрипти, які читають CSV і друкують зведення в консоль. Без аргументів
беруть найновіший файл, або передай шлях:

| скрипт | про що |
|---|---|
| `trail_report.py` | trail braking: скільки гальмування зроблено вже в повороті |
| `drift_report.py` | кут заносу, час боком, перекладки, зриви |
| `analyze_ac.py` | загальне зведення по стінту: тиски, температури, баланс |
| `race_report.py` | кола по стінтах: час, тиски, температури |
| `summarize.py`, `brno_summary.py` | швидкі зведення по ключовому слову в шляху |

Вивід українською. Вони працюють з логами обох ігор — колонки, яких у ACC немає,
пропускаються.

## probe_sim.py

Діагностика: читає поля shared memory живцем і каже, чи виглядають вони
осмислено. Треба, коли гра оновилась і є підозра, що зсунулись офсети структур.
Запускай **на треку**:

```
python probe_sim.py
```

## Обмеження, про які варто знати

- **Windows only.** Використовується `winreg`, `ctypes.windll` і named shared
  memory — на Linux/Mac це не працює.
- **`surfaceGrip` не логується.** Офіційна дока ACC описує його як коефіцієнт
  зчеплення, але на живій сесії поле повертає рівно нуль. Перевірено на
  sm 1.9 / build 1.7.
- **Піт-лейн не побачиш у CSV.** Файл закривається на в'їзді, тому рядок з
  одиницею просто не встигає записатись — це задум, а не втрата даних.
- **Повільне коло без виїзду** (охолодження, трафік) все ще потрапляє в середню
  витрату палива. Виїзди відсікаються, а от просто повільне коло — ні.
- **Логер створює mapping-и shared memory сам**, якщо запустився раніше за гру.
  На практиці це нікому не мішало, але якщо гра раптом не віддає телеметрію саме
  коли логер стартував першим — дивити треба сюди.

## Зібрати exe самому

```
pip install pyinstaller pystray pillow
python -m PyInstaller --noconfirm --onefile --windowed ^
  --icon stint_logger.ico --name StintLogger ^
  --distpath _build --workpath _build/work ^
  stint_logger.pyw
```

Готовий файл — `_build/StintLogger.exe`, близько 26 МБ (tkinter + Pillow всередині).

`--specpath _build` тут не додавай: PyInstaller шукатиме іконку відносно папки зі
spec-файлом і збірка впаде на `Icon input file ... not found`.
